## What was built

| Route | Component | Behaviour |
| --- | --- | --- |
| `/admin/movies` | `MovieList` | Every Movie including archived (status as text), 20 per page, K12 `Pagination`. Archive opens `ConfirmDialog` titled "Archive movie: ‹title›". Restore needs no confirmation. Success is announced in `LiveRegion` and the list reloads. A stale or missing row reloads the list. |
| `/admin/movies/new` | `CreateMovie` → `MovieForm` | All seven writable fields. Genres and cast are one per line. On success, links replace the form so a second click cannot create a duplicate. |
| `/admin/movies/[id]` | `EditMovie` → `MovieForm` | PATCH with If-Match = loaded version. Archived Movies stay editable (D-79) with a note. On 409 `stale_version` the typed text stays in the form, with a "Load latest version" button. Shows the Movie ID for announcement references. |
| `/admin/announcements` | `AnnouncementList` | Every state with a text badge, last published and last updated (UTC). Publish and unpublish are state-only PATCHes. Deleted rows have no action. |
| `/admin/announcements/new` | `CreateAnnouncement` → `AnnouncementForm` | Draft only (D-79). Title, body and an optional Movie ID (an empty Movie ID means null). |
| `/admin/announcements/[id]` | `EditAnnouncement` → `AnnouncementForm` | Draft: "Save draft" and "Save and publish". Published: "Save" and "Save and unpublish". Content and state go in one PATCH (D-79). Deleted announcements are read-only. |

States: every data view has loading (Suspense fallback, then the client fetch), empty (`DataTable` `emptyMessage`), error (`LoadFailure`: client-owned message, a sign-in link on 401, retry on transient failures) and success (`LiveRegion`) states. Field errors from 422 go to their fields through K12 `FormField`/`TextField` (`aria-invalid` and `aria-describedby`). Keys with no control, such as `request`, appear in the form summary.

## Design notes

- **Authorization stays in the API.** No Server Component reads Admin data or calls a service. The page files only resolve `params`/`searchParams` inside `<Suspense>` (required by `cacheComponents`), and every read and write is a Client Component request to the K3-guarded `/api/v1/admin/*` handlers. An anonymous visitor gets the page shell and a "sign in" error, never data (e2e). This avoided adding a cookie-based page guard to Developer A's K3.
- **No `src/server` imports.** `src/app/admin/_lib/` (a Next.js private folder) declares its own DTO types and validates every response body before use. A unit test scans `src/app/admin/**` for `src/server`, `server-only` and non-K12 `src/components` imports.
- **CSRF and If-Match.** `adminWrite` fetches a fresh token from `GET /api/v1/auth/csrf` for each mutation and sends `X-CSRF-Token`. With a version it also sends `If-Match: "n"`. A failed token fetch never sends the mutation. The browser supplies `Origin`.
- **Error messages are client-owned.** Server `message` text is never shown. Only `fieldErrors` string arrays are passed through, and React renders them as text.
- **Coupling.** The forms take their submit behaviour as callbacks (`onSubmit`, or a list of `AnnouncementFormAction`s each bound to its own request), not a mode flag. `useAdminForm` holds text-only state and never clears it on failure. `useAdminResource` discards out-of-order responses.
- **Only K12 components were used.** No changes to `src/components` are needed or requested.

## Known gaps and unverified items

1. **Announcement delete has no UI.** FR-07 and the A-02 description include soft delete, but this commit's prompt named only "list/edit/publish", so no delete control was added. The API exists (DELETE, D-79). Developer B decides whether to add it here (it probably wants a `ConfirmDialog`) or as a follow-up.
2. **Restore and real archive are not exercised in the UI.** Archive returns 503 until U-02's K8 is wired (D-84). When it is, replace the 503 assertion in `tests/e2e/admin-catalogue.spec.ts` with archive → Archived → restore → Active.
3. **The AT-02/AT-06 public halves** still wait on U-01. The e2e checks only the Admin side.
4. **Manual accessibility checks** (keyboard-only pass, screen-reader announcements, focus visibility) are required by product 5.3 and verification and have not been done. `ConfirmDialog` is Developer A's: it renders `<dialog open>` non-modally, so focus does not move into it. That is A's component behaviour; raise it with A if the manual check finds it a problem.
5. The Movie reference is a free-text UUID field with a hint pointing at the Movie edit page, not a picker. A picker would need a decision on how to search across pages.
6. Unit tests run in a node environment without a DOM (no jsdom dependency was added), so interaction coverage comes from the e2e spec only.
