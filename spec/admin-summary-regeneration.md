# Admin summary regeneration — 23 October 2026

This scoped amendment implements FR-08 / AI-01. The human requested manual Admin regeneration and explicitly delegated resolution of blockers and missing decisions in this chat. The recommendations below are adopted under that authorization. This amendment supersedes prohibitions on Admin summary requests in D-02, D-88, D-98, AI-01, AI-03, SEC-06, AT-07 and the corresponding API, architecture and workflow contracts; public reads remain read-only. No new numbered requirement or decision ID is assigned.

## Contract and acceptance

- An active Admin can select **Regenerate AI summary** on the Admin movie detail/edit page for an active Movie. Archived Movies have no control. Show progress, disable repeated submission during the request, and announce the outcome accessibly. Explain that the current summary becomes pending immediately. Public/User pages gain no mutation control.
- `POST /api/v1/admin/movies/:id/summary/regenerate` accepts strictly `{}` as JSON. Use the existing active-Admin mutation guard, Origin and CSRF checks, body-size limit and safe errors. Malformed/unknown/archived Movie IDs return 404. No If-Match is required because Movie metadata/version is unchanged. Node.js runtime, `maxDuration = 120`, no-store responses, request IDs and no automatic retries.
- The service also checks the Principal role. Consume the new K6 `summary_regeneration` fixed policy, one request per Admin account per 300-second window, before invalidating. Rejection returns 429 with Retry-After and makes no Movie/audit/provider writes. Existing key construction and limiter transactions are reused.
- Under the K7 active Movie update lock, call `markReviewsChanged` and record an atomic K5 `movie.summary_regenerate` / `movie` / `applied` audit entry with actor, request ID and new revision only. This explicitly extends `reviews_revision` to include Admin summary invalidation, even without Review changes. Preserve Movie.version, Reviews and oldest pending time. Existing public summary becomes stale immediately. This also occurs with fewer than three eligible Reviews; no provider call occurs in that case.
- In the same transaction record an attempt with next-attempt time one day later. After commit, await one bounded generation with no transaction open. Explicit Admin requests bypass successful-refresh interval and earlier failure backoff; shared execution lease, budget, quotas, minimum three Reviews, sampling, validation and publication revision guards remain unchanged. Concurrent changes/requests can supersede output safely.
- Expose a named `generateForAdmin(movieId, requesterId)` method; keep `generate(movieId)` for the scheduler. Extend the summary job descriptor with optional requesterId. New manual jobs use trigger `admin_request` and the authenticated requester ID; scheduler jobs retain `scheduler` and null. Add a new backward-compatible migration extending only the trigger CHECK; never modify the shipped migration or run release migrations automatically. Summary jobs remain private.
- Return 200 JSON `{ status: "generated" | "pending" | "insufficient_reviews" }`. Map published/current to generated, insufficient_reviews to insufficient_reviews, all other outcomes and post-commit infrastructure failures to pending. Do not return provider details, output or job IDs. Once invalidation committed, a generation fault must not imply that no mutation happened. Log infrastructure faults using identifiers only.
- For deferred/disabled/duplicate outcomes reset next-attempt time to now in a fresh lock transaction. Other failures retain the one-day backoff. Pending work survives all failures. Recovery uses the existing daily sweep and its successful-refresh interval (possibly 1 or 7 days since the prior success); no prompt retry or immediate recovery guarantee is made. Another explicit request after the Admin throttle may attempt again.

## Verification

Verify role/CSRF/strict input, rate-limit-before-write, missing/archived Movies, unchanged-review regeneration, atomic invalidation/audit and preserved Movie.version, commit before AI, manual job provenance, insufficient reviews, safe pending on provider/infrastructure failure, outcome scheduling, stale publication rejection and scheduled recovery. Use synthetic fixtures/fake AI only. Existing summary, runtime, Admin UI and API checks must continue to pass.
